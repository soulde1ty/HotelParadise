# Hotel Paradise

[English](README.md) | **Русский**

Учебный сайт отеля на Django, SQLite и Bootstrap. Python 3.12 рекомендуется; Django 5.2 LTS.

## Запуск

Из корня проекта:

```bash
python -m venv .venv
```

Активация окружения в Windows:

```powershell
.venv\Scripts\Activate.ps1
```

В macOS / Linux:

```bash
source .venv/bin/activate
```

Установка и запуск:

```bash
pip install -r requirements.txt
python hotel_paradise/manage.py migrate
python hotel_paradise/manage.py seed_demo
python hotel_paradise/manage.py createsuperuser
python hotel_paradise/manage.py runserver
```

Сайт: http://127.0.0.1:8000/ . Админка: http://127.0.0.1:8000/admin/ .
Команда `seed_demo` добавляет три номера с фотографиями из проекта. Повторный запуск заполняет только недостающие переводы стандартных демономеров. Пользовательские переводы и изменённые описания сохраняются. Пароль администратора задаётся через `createsuperuser`, общего пароля нет.

## Языки

Переключатель **EN / RU** находится вверху каждой страницы и доступен на телефоне. Выбор сохраняется в cookie, текущая страница и параметры поиска остаются на месте. При первом посещении учитывается язык браузера; запасной язык — английский.

Переведены меню, страницы, кнопки, формы, стандартные ошибки Django, подтверждения и подписи в админке. Для номеров используются поля названия и описания на английском и русском. Если русский вариант не заполнен, показывается английский. Имена гостей и текст их обращений сохраняются как введены.

Переводы интерфейса: `hotel_paradise/locale/ru/LC_MESSAGES/django.po`. Готовый `django.mo` включён в проект, поэтому для обычного запуска дополнительные инструменты перевода не нужны. Если меняете перевод, установите GNU gettext и выполните из папки `hotel_paradise`:

```bash
python manage.py makemessages -l ru
python manage.py compilemessages
```

Перезапустите сервер после перекомпиляции. При переходе с предыдущей версии выполните `migrate`, затем `seed_demo`, чтобы добавить поля и переводы демономеров.

## Что работает

- Главная страница, каталог и отдельная страница номера.
- Поиск по датам, количеству спален и ванных комнат.
- Бронирование с проверкой дат, доступности и пересечения с другими бронями.
- Расчёт стоимости на сервере: цена за ночь × число ночей.
- Подтверждение брони с её номером и итоговой суммой.
- Форма контактов: сообщение сохраняется в базе, сотрудники видят его в админке.
- Управление номерами, бронированиями и обращениями через Django Admin.
- Отмена бронирования через статус Cancelled или действие Cancel selected bookings.
- Загрузка фотографий номеров; если фотографии нет, используется изображение из проекта.

`Room.available` означает, что номер открыт для бронирований. Занятость определяется по датам подтверждённых броней. День выезда не занят: новый гость может заселиться в тот же день. Отмена освобождает даты, но сохраняет запись о бронировании.

Пожелания гостя необязательны. Даты из поиска передаются на форму бронирования. Повторное открытие страницы после подтверждения не создаёт новую запись.

## Структура

- `hotel_paradise/hotel_paradise/` — настройки и маршруты.
- `room/` — номера, поиск, карточки и команда demo-данных.
- `booking/` — модели, формы, проверка дат и оформление брони.
- `contact/` — сообщения гостей.
- `main/`, `about/`, `service/`, `team/`, `testimonial/` — страницы сайта.
- `templates/` — общий шаблон, поля формы и карточка номера.
- `static/` — CSS, JavaScript и изображения.

Папки приложений находятся внутри `hotel_paradise/`.

## Проверки

```bash
python hotel_paradise/manage.py check
python hotel_paradise/manage.py makemigrations --check --dry-run
python hotel_paradise/manage.py test hotel_paradise/
```

Тесты проверяют бронирование, пересечения дат, отмену, цену, поиск, отправку формы, CSRF и отображение страниц. Они используют отдельную тестовую базу.

## Если уже есть база от старой версии

Сначала сохраните копию `hotel_paradise/db.sqlite3` и загруженных фотографий. Затем выполните `migrate`. Брони с выездом не позже заезда или отрицательной стоимостью нужно исправить до миграции: новые ограничения базы их не допускают. Старые пути изображений `static/img/...` поддерживаются.

Раньше флаг Available выключался после бронирования. После обновления проверьте его в админке: включите у номеров, которые открыты для гостей. Новая логика проверяет занятость по датам, поэтому бронь больше не выключает этот флаг.

## Настройки и границы учебной версии

По умолчанию включён локальный режим DEBUG. Переменные окружения:

- `DJANGO_DEBUG=false` — отключить отладочный режим.
- `DJANGO_SECRET_KEY` — свой секретный ключ; обязателен при выключенной отладке.
- `DJANGO_ALLOWED_HOSTS` — домены через запятую, по умолчанию localhost и 127.0.0.1.

Файл `.env` автоматически не загружается: задавайте переменные в терминале или настройках сервера. Для публикации нужно настроить WSGI/ASGI-сервер, HTTPS, раздачу static/media и резервные копии. `runserver` предназначен для разработки.

Оплата и отправка писем не подключены. Контактная форма сохраняет обращение в админке. Разделы команды, услуг и отзывов остаются демонстрационным содержимым исходного шаблона. Перед реальным использованием замените тексты, контакты и фотографии на данные отеля. Bootstrap JS, шрифты и иконки загружаются из внешних CDN.

Оформление основано на исходном шаблоне HTML Codex; ссылки авторов в подвале сохранены.
